# Mini Notepad — مشروع نظم التشغيل (جامعة صنعاء 2026)

## 1) التشغيل
```
python main.py            # Python 3.8+ مع tkinter (مضمّنة في ويندوز/ماك؛ لينكس: sudo apt install python3-tk)
python -m unittest test_file_service -v   # اختبارات طبقة الملفات
```
الهيكل: `main.py` (التشغيل) · `app.py` (الواجهة والتبويبات) · `file_service.py` (كل تعاملات نظام الملفات) · `autosave.py` (الخيط الخلفي) · `recent_files.py` (الملفات الحديثة).

## 2) ارتباط المشروع بنظم التشغيل
| المحور | ما يفعله البرنامج | استدعاء النظام المقابل |
|---|---|---|
| إدارة الملفات | `open/read` للقراءة، `os.remove`، `os.rename`، `shutil.copy2/move`، `os.stat` | open/read/write/close · unlink · rename · stat (ويندوز: CreateFile, DeleteFile, MoveFileEx) |
| الكتابة الآمنة | كتابة ملف مؤقت ← `fsync` ← `os.replace` ثم إعادة قراءة للتحقق | fsync / FlushFileBuffers · rename ذرّية (Atomic) |
| الصلاحيات | `os.access(W_OK)` قبل الحفظ، وعرض `stat.filemode` (rwxr--r--) | access(2) · st_mode (بتات الصلاحيات) |
| معالجة الأخطاء | تحويل `FileNotFoundError / PermissionError / ...` لرسائل عربية | errno: ENOENT, EACCES, EEXIST, EISDIR |
| الخيوط | خيط خلفي للحفظ التلقائي + `queue.Queue` + `Lock` لكل ملف | pthread_create / CreateThread · Mutex · IPC بالطوابير |
| النقل بين الأقراص | `shutil.move` | rename داخل نفس القرص، وإلا نسخ ثم حذف |

**لماذا الخيط الخلفي؟** كتابة القرص عملية بطيئة (I/O-bound)، فتُنفَّذ في خيط مستقل كي لا تتجمد الواجهة. وTkinter ليس آمناً للخيوط، لذا الخيط الخلفي لا يلمس الواجهة أبداً؛ يتواصل مع خيط الواجهة عبر طابورين (jobs / results). القفل `Lock` يمنع تداخل الحفظ اليدوي مع التلقائي على الملف نفسه (Race Condition).

## 3) دليل الاختبار
- **ملف جديد/تنبيه:** اكتب نصاً ثم Ctrl+N ← يظهر تنبيه (حفظ / عدم الحفظ / إلغاء).
- **فتح/حفظ/حفظ باسم:** افتح ملفاً، عدّله، Ctrl+S ← "تم الحفظ بنجاح". جرّب حفظ باسم بلا امتداد ← يُضاف `.txt`.
- **قراءة فقط:** لينكس `chmod 444 f.txt` / ويندوز: خصائص الملف ← Read-only. افتحه ← الشريط السفلي "للقراءة فقط"؛ Ctrl+S ← رسالة خطأ واضحة؛ الحفظ التلقائي يتجاوزه. (ملاحظة: المستخدم root يتجاوز الصلاحيات في لينكس.)
- **ملف محذوف من الحديثة:** افتح ملفاً، أغلقه، احذفه من مستكشف الملفات، ثم اخترته من «الملفات الحديثة» ← تحذير ويُزال من القائمة.
- **تعديلات غير محفوظة:** عدّل ثم أغلق التبويب أو البرنامج ← رسالة التأكيد (علامة * على التبويب).
- **الحفظ التلقائي:** من القائمة اجعل الفترة 5 ثوان، عدّل ملفاً محفوظاً وانتظر ← "تم الحفظ التلقائي" وتختفي *. الملفات الجديدة تُحفظ نسخة استرجاع في `~/.mini_notepad/recovery`.
- **بحث:** Ctrl+F ← تمييز كل النتائج، التالي/السابق، وكلمة غير موجودة ← إشعار.
- **حذف/إعادة تسمية/نسخ/نقل:** من قائمة «إدارة الملفات»، جرّب اسماً موجوداً مسبقاً وملفاً بلا صلاحية.
- **تراجع/إعادة:** Ctrl+Z / Ctrl+Y بعد عدة تعديلات.

## 5) أسئلة شفوية متوقعة
1. لماذا نكتب في ملف مؤقت ثم `os.replace`؟ ← لضمان الذرّية فلا يتلف الملف عند انقطاع الكهرباء.
2. ما فائدة `fsync`؟ ← يجبر النظام على تفريغ ذاكرة التخزين المؤقت للقرص.
3. كيف تعرف أن الملف للقراءة فقط؟ ← `os.access` وبتات `st_mode`.
4. لماذا الخيط الخلفي ولا نلمس الواجهة منه؟ ← Tkinter غير Thread-safe؛ نستخدم طابوراً.
5. ما الـ Race Condition وكيف تفاديتها؟ ← Lock لكل ملف + لقطة نصية (snapshot).
6. الفرق بين Thread وProcess؟ وما أثر GIL؟ ← الخيوط تتشارك الذاكرة؛ GIL لا يضر هنا لأن المهمة I/O.
7. ماذا يحدث عند نقل ملف بين قرصين؟ ← نسخ ثم حذف بدل rename.
8. ما الفرق بين مسار مطلق ونسبي؟ ولماذا `abspath`؟
9. ماذا تعني رموز الأخطاء ENOENT/EACCES؟
10. كيف يعمل Undo/Redo؟ ← مكدّسان (Stack) داخل ويدجت Text.
